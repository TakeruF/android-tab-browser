# 共通広告枠処理の検証 — 2026-10-11

QA エミュレーター上の最新 Github Debug APK で、12 サイトのトップページ、
BBC・AP の記事ページを検証した。スマホ幅で 14 URL、大画面で 4 URL の計 18 条件。
スクロール後を含む 32 回の DOM 計測と画面保存を行った。
朝日新聞専用の追加ルールを削除した状態での結果である。

## 環境と方法

- 対象: `emulator-5554` / `Nagi_Foldable_UI_QA` / Android 16 / WebView 133。
- スマホ: 720×1640 px、density 320、Nagi のウィンドウ幅 360dp。
- 大画面: 1600×2000 px、density 320、ウィンドウ幅 800dp、サイドバー表示。
- 各ページで URL、UA、UA Client Hints、見出し、画像、ナビゲーション、入力欄、
  共通処理が付けたマーカーと枠の高さを取得した。
- 同じ DOM で共通処理の非表示 CSS だけを同期的に外して測定し、必ず元に戻した。
  元の広告フィルターは維持し、リロードや広告の再取得は行っていない。
- 非表示になった親要素は最上位のものだけを数え、重複を避けて高さを合計した。
  下表の高さは CSS px。この合計はページ全体の高さの差や削除した広告数ではない。
- 比較対象は `h1/h2/h3/article/nav/header/img/input/textarea/select/button/a[href]`。
  共通処理の追加で、それまで表示されていた比較対象が隠れるケースは 32 計測すべてで 0。
  実際の画面でも見出し・記事写真・操作部品を確認した。
- ログイン、登録、フォーム送信、Cookie の承諾は行っていない。
  ユーザー使用中の別エミュレーターと接続実機には変更を加えていない。

## サイズ変更と入力保持

GitHub の大画面タブのメール欄に QA 用の値を設定し、DOM の識別トークンを付けた。
スマホ幅に変更した後もトークン、入力値、URL、UA は同じで、文書が保持された。
その後の明示的な百度へのページ表示では、Mobile UA と `mobile: true` に切り替わった。
サイズ変更に伴う自動リロードは発生していない。
設定済みのユーザー選択や逆方向の変更は、既存の WebView 回帰テストで確認している。

## 回帰検証と限界

ユニット 147 件、WebView/UI 13 件が成功。Lint と Github Debug ビルドも成功した。
WebView 回帰には、任意の 2 ドメインの空の広告親枠、実際にブロックした画像・iframe、
本文・入力・画像・CSS 描画の保護、遅れて追加された要素、本文追加時の再表示、
広告ブロックの停止・再開、サイズ変更と非表示タブ・Split の入力保持が含まれる。

腾讯の残った枠は、既存フィルターやブロック済みメディア URL から広告と判定できていない。
DOM に広告文言と通常のテキスト・操作要素があるため、一般の空白削除では解決できない。
広告検出のカバレッジとして残課題を記録した。サイト名やこのサイトのクラスを
共通コントローラーへ追加する変更は行っていない。

検証は上記ページの確認時点のエミュレーター結果である。Cookie・利用案内以降の操作、
ログイン後、すべての記事、すべての端末や広告配信パターンを確認したものではない。

DOM JSON、画像、再実行スクリプト、入力保持の証拠、最終ビルドログと APK は
Git 管理対象外の `artifacts/general-ad-collapse/` に保存している。
